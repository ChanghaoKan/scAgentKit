# 注释阶段的证据查证

本指南适用于开发版。用 `sc_start(input, project_dir, context=..., provider=...)`
新建项目。交互式 R 中，一次确认汇总数据外发范围，网页随后准备供你审阅的草稿。
非交互调用可用安装包中的 `full-llm-workflow.R` 示例显式记录确认。
`review=list(allow_external=TRUE)` 保留每次请求单独确认的严格模式。

第一关提供 QC 和批次诊断证据；诊断簇不是最终细胞类型，批准后重新计算正式分析。
第二关复核实际分群结果。第三关先独立生成注释，再与本地 ACT 对比。
默认 `react="auto"` 查证低置信度、Unknown 或与 ACT 冲突的簇；
`react="all"` 查证全部簇，`react="off"` 保留一次性草稿与本地参考对比。
重开项目使用已保存的配置。

查证只能读取已保存的 marker、表达汇总、ACT 条目与簇背景，不能修改数据或批准决定。
单纯表达结果标为“未检验”；支持标签的统计 marker 必须通过确定性引用校验。
证据不足时应给出粗粒度标签或 Unknown。你仍可以修改草稿，再明确批准。

在注释行展开查证过程，可看到查询内容、返回证据与草稿结论；点击引用可跳转对应步骤。
顶部汇总工具调用、实际记录的用量、费用与回退原因。未知费用不会记作零。
默认每簇最多六轮、每会话六十轮、每簇三分钟。新启动流程默认事后记账，不做预估或
额度预留，不设金额上限。

模型不支持工具、超时、达到步数上限或输出未通过校验时，退回已有的一次性草稿并显示原因。
如果连有效初稿都没有，仍可手动注释。投递不确定的请求不会自动重发。
输入或审计完整性损坏仍会阻断，不会悄悄换掉证据。

本地演示可 source 安装示例 `react-three-gate-mock.R`，调用
`react_three_gate_mock(新项目目录, 新输入RDS路径)`。它使用公开 `pbmc_small`、
显式脚本审批和 mock 模型，不调用真实 API。这是软件验收，不是生物学验证；
不要把其中自动采纳的审批策略直接用于自己的研究数据。
