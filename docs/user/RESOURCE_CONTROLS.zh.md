# 请求容量与本地存储

新项目可设置 `sc_start(..., react=list(mode="auto", max_payload_bytes=400000L))`。
新项目默认 max_payload_bytes="unlimited"，关闭应用字节配额。显式有限值可设为
1–1,000,000 UTF-8 字节，控制一次性请求和 ReAct 完整会话。扫描摘要使用实际
扣除其他提示词与证据之后的剩余空间，保留来源 hash 和遗漏块清单。其他证据和提示词仍须放入
完整请求；超限就退回本地审阅，不静默截断。重开项目沿用已保存的配置。

这是应用容量保护，不是供应商 token/上下文上限，也不是金额封顶。放大字节值
不保证模型一定能接收；按具体型号检查上下文容量尚未实现。研究背景自由文本、
单次工具结果仍有独立隐私和资源限制。各入口统一事后记账，不设金额上限。

`model_timeout=NULL` 根据已保存的 ReAct 步数、每簇时限和 provider 超时，
加上启动/收尾余量推导整次请求的上限，不再统一套用 300 秒。也可显式指定
1–86,400 秒，包括更短的操作限制。自动值最多 24 小时，极大的自定义配置仍
可能触达这个上限。每簇、工具和 provider 的内部时限仍生效。投递不确定不自动重发。

marker 与 ACT 查询可使用返回的 next_offset 继续取下一页，保持相同查询和
已保存输入。每页给出偏移、总可用数、返回数和是否部分结果；完整证据始终在本地。
每次返回大小与会话步数仍有限。后续 marker 页的引用统计条件和第一页完全相同。

审阅页的“Measure local storage”按钮按需统计项目占用，不跟随符号链接，也不
删除任何文件。统计有执行边界，未完成时明确显示“部分下界”。这是逻辑文件大小，
不等同于实际磁盘分配量或剩余磁盘空间。

归档时先完成或停止活动 worker，再复制整个项目并保持目录结构，逐文件核对复制
前后的 hash。另存原始输入以及 R、包和依赖环境记录。归档未验证之前保留原项目；
是否删除原项目由你明确决定。审阅 ZIP 不能替代完整科学项目备份。
本阶段尚未实现自动归档、日志分段和审阅包/显示大小的配置扩展。
